# Data

| File | What it is | Source |
|---|---|---|
| `provider_features.csv` | Provider-level feature table (5,410 providers, 506 labeled fraudulent), 5-fold assignment in column `fold`, derived by `src/01_build_features.py` | Kaggle "Healthcare Provider Fraud Detection Analysis" (rohitrox, 2019) |
| `cms_2018_2019_merged.csv.gz` | Provider-level panel: NPI, beneficiaries and mean patient age in 2018 and 2019, provider type (inner join on NPI) | CMS Medicare Physician & Other Practitioners - by Provider, 2018 and 2019 releases |
| `cms_2021_2022_merged.csv.gz` | Same, 2021 and 2022 | CMS Medicare Physician & Other Practitioners - by Provider, 2021 and 2022 releases |

Use the "by Provider" release (file name ends in `_Prov.csv`). The "by Provider and Service" release is at
procedure-code level and has no beneficiary demographics.

The Kaggle file's beneficiary-to-provider linkage is close to random (observed/expected variance ratio of mean patient
age = 1.012; for CMS it is far larger), so it should be treated as synthetic or semi-synthetic (see paper, Section III-A).
CMS files are public use files released by the Centers for Medicare & Medicaid Services (U.S. government data, no data use agreement). The two merged year-pair panels here contain only provider-level aggregates derived from those files and are redistributed under that release; the original CMS files are not included.

## Raw Kaggle files (not redistributed here)

To rebuild `provider_features.csv`, download the dataset "Healthcare Provider Fraud Detection Analysis" from Kaggle and place these
four files in `data/raw/` (that folder is git-ignored):

- `Train_Beneficiarydata-1542865627584.csv`
- `Train_Inpatientdata-1542865627584.csv`
- `Train_Outpatientdata-1542865627584.csv`
- `Train-1542865627584.csv`

then run `python src/01_build_features.py`; it checks the result (5,410 providers, 506 fraud, no missing values).

## Optional external files (not redistributed)

| File | Used by | Where to get it |
|---|---|---|
| CMS 2022 "Medicare Physician & Other Practitioners - by Provider" (`MUP_PHY_R25_P07_V20_D22_Prov.csv`, about 1.2 million providers) | `src/make_cms2022_extract.py` (writes `cms2022_extract.csv.gz`, providers with more than ten beneficiaries), `src/cms_stage0_sweep.py`, `src/flag_rate_*.py`, `src/table12_cms.py` | data.cms.gov, accessed October 2026 |
| OIG List of Excluded Individuals and Entities, `UPDATED.csv` (about 15 MB) | `src/leie_cms_check.py`, `src/flag_rate_*.py` (labels: exclusion dates from 2023-01-01, 416 providers matched by NPI) | oig.hhs.gov, "LEIE Downloadable Databases", accessed October 2026 |
| Kaggle "Healthcare Provider Fraud Detection Analysis" raw files | `src/01_build_features.py`, `src/permutation_null.py`, `src/beneficiary_level_variance.py` | kaggle.com, accessed October 2026 |

Pass the first two as arguments, for example `python run_all.py --cms2022 cms2022_extract.csv.gz --leie UPDATED.csv`.
The LEIE check fits a classifier on a random split, so its point estimates, in particular the size slope among excluded providers,
change with the seed (Table S14 of the supplement reports the reference run and the range over 20 seeds).

## Large intermediate file (not in the GitHub repository)

`output/flag_rate_flags.csv.gz` (27 MB; the out-of-fold flags of the two screening models, written by `src/flag_rate_predict.py`) is too large for the
GitHub web upload and is not included there. It is regenerated by `python src/flag_rate_predict.py cms2022_extract.csv.gz UPDATED.csv`
and is attached to the Zenodo archive. `src/flag_rate_observe.py` and `src/table12_cms.py` read it.
